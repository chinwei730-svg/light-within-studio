# 未來擴展版：網站架構規劃

分支：`future-expansion`（設計預覽用，不上線）
正式站：`main`（純奧剛課程，GitHub Pages 目前指向這裡）

---

## 一、核心問題

課程從 2 門長到十幾門、領域從 1 個變成 4 個之後，
**首頁不能再是一份課程清單**，Hero 也不能再替某一門課說話。

解法是把「一層」拆成「三層」，每一層只回答一個問題：

| 層級 | 頁面 | 回答的問題 | 課程變多時 |
| --- | --- | --- | --- |
| 1 品牌層 | `index.html` | 這裡是誰？有哪幾種東西？ | **長度不變** |
| 2 領域層 | `orgonite.html` `mandala.html` `tarot.html` `bazi.html` | 這個領域在做什麼？有哪些課？ | 多一張卡片 |
| 3 課程層 | `course-trial.html` 等 | 這門課上什麼？多少錢？怎麼報名？ | 多一個檔案 |

課程數量的成長被吸收在第 2 層，第 1 層永遠只有四個入口。

---

## 二、首頁 Hero 怎麼處理

四個領域之後，Hero 只講品牌共通的那一句話，不講任何一門課：

```
芯光點點
Light Within Studio
四條路，通往同一件事
手作的溫度、色彩的靜心、牌卡的提醒、命盤的地圖——
不論你從哪一個開始，都是往自己走近一點。

[Orgonite 奧剛能量藝術] [Mandala 曼陀羅] [Tarot 塔羅占卜] [BaZi 八字命理]

            〔探索四大領域〕
```

關鍵是標題底下那**四顆膠囊**：
訪客第一眼就知道「這裡有四種東西」，而且可以直接點進去，
不必先捲動、也不用猜導覽列裡哪一個是自己要的。

**沒有採用的做法與原因：**

- ❌ 輪播（carousel）四個領域 — 一次只看得到一個，其他三個等於不存在；手機上尤其糟。
- ❌ Hero 直接放課程卡片 — 課程一多就爆版，而且第一眼給的是價目表不是品牌。
- ❌ 四張全螢幕分割 — 好看，但手機變成要捲四個螢幕才看得完。

---

## 三、四大領域總覽（首頁第二區塊）

首頁**只列領域，不列完整課表**。每張領域卡片給的是：

```
┌─────────────────────┐
│  照片                │
├─────────────────────┤
│ ORGONITE            │  ← 英文小標（配色 = 該領域主色）
│ 奧剛能量藝術          │
│ 一句話說清楚在做什麼    │
│ ─────────────────── │
│ 體驗班    3 小時・3,600│  ← 只露 2~3 門代表課程
│ 精修二日班 13 小時・15,900│
│ ─────────────────── │
│ 查看奧剛全部課程 →     │
└─────────────────────┘
```

代表課程是「預告」不是「清單」——它的作用是讓人知道這個領域的價位帶與時間長度，
決定要不要點進去。完整課表永遠在領域頁。

---

## 四、四個領域怎麼區分

共用同一套版型與金色品牌調性，但每個領域有一個**低彩度輔色**，
掛在 `<body class="theme-xxx">` 上，整頁的強調色就跟著換：

| 領域 | class | 色碼 | 用在哪 |
| --- | --- | --- | --- |
| 奧剛 | `theme-orgonite` | `#C9A961` 金 | 品牌主色，維持現狀 |
| 曼陀羅 | `theme-mandala` | `#C08A6E` 陶橘 | 卡片上緣線、標籤、按鈕 |
| 塔羅 | `theme-tarot` | `#8279A8` 星紫 | 同上 |
| 八字 | `theme-bazi` | `#5F7A82` 墨青 | 同上 |

目的不是讓網站變花，而是讓訪客在四個領域之間跳來跳去時，
能靠一條線、一個標籤的顏色知道自己現在在哪一區。

## 五、導覽列

```
Logo   關於我們   奧剛能量藝術▾   曼陀羅▾   塔羅占卜▾   八字命理▾
                  ├ 認識奧剛
                  ├ 體驗班・3 小時
                  ├ 精修二日班・13 小時
                  └ 全部奧剛課程
```

- 每個領域名稱**本身就是連結**（進領域頁），下拉只是捷徑。
- 還沒開的課先列出來但**不做成連結**（灰字「籌備中」），讓訪客知道之後會有。
- 手機沒有 hover，下拉自動攤平成縮排子項目，不需要額外的展開按鈕。
- 導覽列永遠只有一層。課程再多，都被收在下拉裡。

## 六、領域頁的固定結構

四頁完全一樣，只換文字與配色：

1. **領域頁首** — 一句話說清楚這個領域在做什麼 + 現有課程數／上課形式／適合對象
2. **這是什麼** — 給第一次來的人的說明
3. **課程一覽** — 篩選列（全部／入門／進階）+ 課程卡片
4. **常見問題** — 3 則
5. **報名 CTA** + 頁尾

課程卡片統一露出「時數／費用／作品」三欄 meta，
讓同一個領域裡的幾門課可以**橫向比較**，不必一張張點進去看。

課程超過四、五門之後，上方的篩選列開始有用；在那之前它不會礙事。

## 七、新增一門課要做什麼

1. 照片放進 `images/<領域>/course/`，接續該資料夾的號碼；簡章放 `pdf/<領域>/`
2. 複製 `course-trial.html` → 改名、改文字、改圖
3. 在對應領域頁 `xxx.html` 的 `.course-grid` 裡複製一張 `.course-card`，補 `data-level="intro|advanced"`
4. 在導覽列該領域的 `.nav-sub` 加一行
5.（可選）如果要當代表課程，在首頁該領域卡片的 `.service-courses` 加一行
6. 補 `sitemap.xml`

**不需要動 CSS。**

## 八、資料夾：資料夾決定領域，檔名決定用途

以前只有奧剛，所有課程照片放 `images/course/` 就夠了。四個領域之後，
`c_0027.jpg` 光看檔名分不出是誰的，所以照領域拆開：

```
images/
  common/     title/  about_us/        ← 四個領域共用（logo、教室環境）
  orgonite/   course/  showcase/
  mandala/    course/  showcase/
  tarot/      course/  showcase/
  bazi/       course/  showcase/
pdf/
  orgonite/  mandala/  tarot/  bazi/
```

**檔名規則完全沒有改**，還是 `t_` `a_` `c_` `s_` 加四位流水號，
只是流水號在各自的資料夾裡從 0001 重新開始——領域由資料夾決定，
不必在檔名裡再寫一次。換照片一樣是直接覆蓋同檔名，不用改 HTML。

完整說明（含 HEIC 原始檔的擺法）見 `images/資料夾與命名規則.txt`。

> 這個搬移只做在 `future-expansion` 分支。`main` 維持原樣，
> 因為線上的 og:image 與結構化資料都是絕對網址、已經被收錄，
> 現在動會讓社群分享的預覽圖失效。等擴充版正式上線時一起換。

## 九、新增一個領域要做什麼

1. 複製任一領域頁 → 改名、改文字
2. 建 `images/<領域>/course/`、`images/<領域>/showcase/`、`pdf/<領域>/`
3. `css/style.css` 加一組 `.theme-xxx` 色票（4 行）
4. 導覽列與首頁各加一塊（複製既有的改文字）

## 十、還沒定案、需要老師決定的事

- [ ] 曼陀羅／塔羅／八字的**課程名稱、時數、費用、班制**
- [ ] 塔羅與八字：**占卜／解盤服務**和**教學課程**要放同一頁還是拆開
- [ ] 「關於我們」文案要重寫成涵蓋四個領域的版本（目前的初稿只是暫代）
- [ ] 首頁「作品展示」目前全是奧剛作品，曼陀羅開課後要混入畫作或改成分頁籤
- [ ] 各領域的照片（每個領域至少：主視覺 1 張、說明 1 張、每門課 1 張）
- [ ] 立場說明（塔羅／八字這類服務，建議比照 `what-is-orgonite.html` 的作法寫清楚）

頁面上所有還沒定案的文字都寫成〔文案待定〕，
照片都用工作室 logo 當預留圖並標「照片準備中」，不會有假資料混進去。
